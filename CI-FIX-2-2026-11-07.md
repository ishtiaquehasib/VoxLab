## Exact cause (proven, not guessed)

`espeakng_loader.get_data_path()` (espeakng-loader 0.2.4) is:

```python
data_path = Path(__file__).parent / 'espeak-ng-data'
if not data_path.exists():
    raise RuntimeError(f'data path not exists at {data_path}')
```

and `kokoro_onnx/tokenizer.py` calls it on every `Tokenizer()` init,
i.e. on every Kokoro ONNX generate. In a PyInstaller one-dir build the
module lives in `dist/VoxLab/_internal/espeakng_loader/__init__.py`
(inside the PYZ archive), so the data must sit at
`dist/VoxLab/_internal/espeakng_loader/espeak-ng-data` — but no workflow
collected it. `--collect-all kokoro_onnx` collects only kokoro_onnx's
own files; there was no `--collect-all espeakng_loader`, no
`--collect-data`, no `--add-data` for it in any workflow. PyInstaller
collects a package's `.py` into the PYZ but NOT its data directory
(~19 MB) or its shared library (`espeak-ng.dll` on Windows,
`libespeak-ng.so` on Linux, `.dylib` on macOS — ctypes-loaded, so static
binary analysis never sees it either). The data error fires first
(`get_data_path()` runs before `get_library_path()`), so the missing
DLL was hidden behind it.

Why Linux passed: `/api/generate` tries the PyTorch `kokoro` KPipeline
first and only falls back to the ONNX route when it fails
(`backend/server.py` ~line 493). On the Linux runner the KPipeline path
succeeded (phonemizer found a system espeak-ng there), so the ONNX
route — and its missing data dir — was never exercised. Linux #19
therefore does NOT prove the ONNX route works on Linux either; the
bundle check below now proves it on every platform. (Inference from
the code path + the two runs' outcomes, stated as such.)

## The fix

All 3 workflows (`.github/workflows/{windows,linux,macos}-installer.yml`):

1. **`--collect-all espeakng_loader`** added to the PyInstaller command,
   right after `--collect-all kokoro_onnx`. `--collect-all` collects the
   package's data files AND binaries, so `espeak-ng-data/` (19 MB) and
   the platform shared library both land in
   `_internal/espeakng_loader/` — exactly where `get_data_path()` /
   `get_library_path()` look. No backend code change needed.
2. **New pre-smoke step "Verify espeak-ng data bundled"** right after
   "Build with PyInstaller" (before windowed-check / slim / smoke):
   asserts the data dir AND the platform library exist in `dist/`,
   fails the job with a clear message if either is missing — instead
   of a 31 s smoke failure. (Linux slim step runs after this check and
   cannot delete the data: it only removes `__pycache__` / `*.pyc` /
   torch test/include/share / CUDA / nvidia / `*.pyi` paths.)
3. Workflow header comments updated to the honest v1.1.7 status.
4. `PARITY.md`: short v1.1.8 entry in the frozen-gate section.

Files changed (local only, NOT pushed): 3 workflows + `PARITY.md` +
this report (`CI-FIX-2-2026-11-07.md`, new). No `.py` changed.

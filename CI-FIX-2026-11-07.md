## What broke (per platform)

### 1. Windows installer #19 — FAILED at "Download + bundle Kokoro ONNX (A-Z gate)"
- Error: `python backend/ci_bundle_kokoro.py` line 24
  `from huggingface_hub import snapshot_download` →
  `ModuleNotFoundError: No module named 'huggingface_hub'`.
  All earlier steps passed.
- Root cause (as far as it can be determined from here): the bundle
  step depended on a package the resolver may or may not install.
  transformers 5.2.0 (which pip resolves for chatterbox 0.1.7) DOES
  declare `huggingface-hub<2.0,>=1.3.0`, and the fixed-set dry-run
  below resolves huggingface_hub 1.33.0 — so the hub *should* have
  been present, and the exact Windows cause (resolver backtracking
  vs pip/python mismatch on the runner) is NOT determinable from
  this VM. The fix removes the dependency instead of guessing.
- **Second latent bug found by testing the fix:** the script
  downloaded from hexgrad/Kokoro-82M, which does NOT contain
  kokoro-v1.0.onnx or voices-v1.0.bin at all (verified 2026-11-07
  via the Hugging Face API: that repo holds kokoro-v1_0.pth +
  voices/*.pt only). snapshot_download would have failed next with
  "not in snapshot" even with the import fixed. The v1.1.6 bundle
  step was doubly broken; only the first failure was visible in CI.

### 2. Linux installer #18 — FAILED at "Install dependencies" (36 s)
- Error: pip ResolutionImpossible — kokoro-onnx 0.6.1 needs
  numpy>=2.0.2 while chatterbox-tts 0.1.4–0.1.7 needs numpy<2.0.0,
  and transformers>=4.57 conflicts with chatterbox pinning
  transformers==4.46.3.
- Root cause (verified from git + PyPI metadata): the ONLY
  requirements.txt change in v1.1.6 was ADDING `kokoro-onnx==0.6.1`
  (+ onnxruntime==1.31.1). v1.1.5 passed because kokoro-onnx was
  never in the resolution set. The conflict is fundamental, not a
  version-picking accident: EVERY kokoro-onnx version >=0.4.7
  declares numpy>=2.0.2, while EVERY chatterbox-tts version on
  Python 3.12 declares numpy<2.0.0 (0.1.7: numpy<2.0.0,>=1.24.0;
  0.1.4–0.1.6: numpy<1.26.0,>=1.24.0). No resolver can satisfy both
  in one install. The transformers half: chatterbox 0.1.4–0.1.6 pin
  transformers==4.46.3, which rejects transformers>=4.57; only
  0.1.7 pins transformers==5.2.0 (consistent with the file).

## The fixes (minimal, in ~/workspace/voice-studio/)

### Fix 1 — `backend/ci_bundle_kokoro.py`: urllib download from the right source
- `snapshot_download` replaced with stdlib `urllib.request` download
  (`download_file()` with 3 attempts, streaming to disk, size gate).
  The step now has ZERO package dependencies, so it cannot fail with
  a missing import again.
- Source corrected to the kokoro-onnx project's own release assets:
  `https://github.com/thewh1teagle/kokoro-onnx/releases/download/model-files-v1.0/{kokoro-v1.0.onnx,voices-v1.0.bin}`.
  Docstring + PARITY.md corrected (they claimed hexgrad/Kokoro-82M).
- NOTE: the first version of this fix kept the wrong source (only
  the transport changed) and the end-to-end test 404'd — that test
  caught the second bug before CI could. The corrected script was
  then re-tested end-to-end (see verification).

### Fix 2 — `backend/requirements.txt`: kokoro-onnx OUT, chatterbox pinned
- `kokoro-onnx==0.6.1` REMOVED (with a comment explaining why and
  forbidding re-adding it without re-checking). `onnxruntime==1.31.1`
  STAYS — its numpy>=1.21.6 is compatible with numpy<2, so it
  resolves normally.
- `chatterbox-tts` (unpinned) → `chatterbox-tts==0.1.7`: the only
  chatterbox whose pins are consistent with this file
  (transformers==5.2.0, torch==2.6.0, numpy<2.0.0). Makes CI
  resolution deterministic instead of depending on the latest
  chatterbox release.
- No other line touched.

### Fix 3 — all 3 installer workflows: install kokoro-onnx `--no-deps` after numpy<2
- New step "Install Kokoro ONNX (no-deps, numpy<2 compatible)",
  placed after "Install dependencies" and before the verify steps:
  `pip install --no-deps "kokoro-onnx==0.6.1"`, then
  `pip install "phonemizer>=3.4.0" "espeakng-loader>=0.2.4" "colorlog"`,
  then an import check (`kokoro_onnx`, `onnxruntime`,
  `huggingface_hub`, `numpy` version printed) that fails the job
  here — not later at the bundle step — if the install ever stops
  importing.
- Why `--no-deps` is safe: the kokoro_onnx 0.6.1 wheel is pure
  Python (py3-none-any); its only runtime deps are onnxruntime
  (already in requirements.txt) + phonemizer + espeakng-loader,
  and none of those declare numpy>=2 (phonemizer 3.4.0 needs
  joblib/attrs/dlinfo/typing-extensions; espeakng-loader has no
  deps). The unsatisfiable metadata is kokoro-onnx's own
  `numpy>=2.0.2` line, not a real runtime need — proven by the
  runtime test below.
- Workflow header comments updated to the honest v1.1.6 status
  (they still claimed no real CI run had happened).
